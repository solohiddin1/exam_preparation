🎯 2. Keyword arguments

Here you name each argument, so order doesn’t matter:

You can even mix them — but positional args must come first:

greet("Solohiddin", message="Hey")  # ✅
greet(name="Solohiddin", "Hey")     # ❌ Error

💾 3. Default arguments

You can give a parameter a default value:

def greet(name, message="Hello"):
    print(f"{message}, {name}!")

Now you can call it either way:

greet("Solohiddin")           # → Hello, Solohiddin!
greet("Solohiddin", "Hiya")   # → Hiya, Solohiddin!

Important rule:
➡️ Default values are evaluated once, at function definition time.

That means this can be dangerous:

def add_item(item, items=[]):
    items.append(item)
    return items

print(add_item(1))  # [1]
print(add_item(2))  # [1, 2] ← unexpected!

Better:

def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

Can you guess why the first version keeps adding to the same list?
(Hint: where does Python store the default value?)
🌀 4. *args — variable positional arguments

If you don’t know how many args you’ll get:

    return sum(nums)

print(add_all(1, 2, 3))  # → 6

*args collects extra positional arguments into a tuple.
Inside the function, args acts like (1, 2, 3).
🧩 5. **kwargs — variable keyword arguments

Collects extra keyword args into a dictionary:

    Positional

    *args

    Keyword-only

⚙️ Step 3 — Wrapping a function

A decorator is basically a wrapper function that adds behavior before/after another function runs.

Let’s make one manually first.

def log_decorator(func):
    def wrapper():
        print("Function is about to run")
        func()
        print("Function finished running")
    return wrapper

🪄 Step 4 — The @ syntax

The @decorator_name is just syntactic sugar for that manual wrapping.

That’s identical to:

💡 Step 5 — Handling arguments

What if your original function takes parameters?

def log_decorator(func):
    def wrapper(*args, **kwargs):
        print(f"Running {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Finished {func.__name__}")
        return result
    return wrapper

🔄 Step 6 — Preserving metadata (optional but common)

When you decorate a function, Python replaces the original function’s __name__, __doc__, etc. with those of the wrapper.
To fix that, use:

from functools import wraps

def log_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

Now add.__name__ will still be "add" instead of "wrapper".

🧩 The structure of a basic decorator

def decorator(func):      # ① Outer function
    def wrapper(*args, **kwargs):   # ② Inner function (the wrapper)
        # code that runs before
        result = func(*args, **kwargs)
        # code that runs after
        return result
    return wrapper         # ③ Return the wrapper itself

✅ decorator — the outer function — gets called first when Python sees @decorator.
✅ wrapper — the inner function — is what actually runs every time you call your decorated function.

So when you write:

@decorator
def greet():
    print("Hi")

Python secretly does:

greet = decorator(greet)

and inside decorator, you return wrapper.
That means greet now is wrapper.
When you call greet(), you’re actually calling wrapper() — which runs func() inside it.
🪄 Decorators that take arguments (the “three-layer” version)

Now, to add decorator arguments, we need one more layer of functions.

Here’s the pattern:

def decorator_with_args(n):          # ① outermost — receives the decorator argument
    def actual_decorator(func):      # ② normal decorator — receives the function
        def wrapper(*args, **kwargs):# ③ inner wrapper — wraps the function call
            for _ in range(n):
                func(*args, **kwargs)
        return wrapper
    return actual_decorator

Usage:

@decorator_with_args(3)
def say_hi():
    print("hi")

hi

    def print_name(self):
        print(self._name)

    “This is internal, don’t touch it outside the class or subclass.”

🧠 Concurrency & Parallelism — aka threads and processes.

This is one of the trickiest but most impressive topics — and it shows deep Python understanding when you explain it well in an interview or exam.
🧩 Step 1 — The Core Idea
🧵 Threading → “doing multiple things at once” in one process.
⚙️ Multiprocessing → “doing multiple things truly in parallel” across multiple CPU cores.

So both let your program “do more at once” — but in different ways.
🧠 Step 2 — Why It Exists

Imagine this simple code:

import time

def task(name):
    print(f"Starting {name}")
    time.sleep(3)
    print(f"Finished {name}")

task("A")
task("B")

➡️ This takes 6 seconds total because both tasks run one after another.

But sometimes tasks don’t need to wait for each other —
for example, downloading files or waiting for API responses.

That’s where threads come in.
🧵 Step 3 — Threading Example

import threading
import time

def task(name):
    print(f"Starting {name}")
    time.sleep(3)
    print(f"Finished {name}")

t1 = threading.Thread(target=task, args=("A",))
t2 = threading.Thread(target=task, args=("B",))

t1.start()
t2.start()

t1.join()
t2.join()

print("All done!")

🧩 Output:

Starting A
Starting B
Finished A
Finished B
All done!

✅ Takes only ~3 seconds total, not 6.
Because both threads run concurrently.
⚠️ Step 4 — But Threading Has a Limit (GIL)

Python has something called the Global Interpreter Lock (GIL).
It means that even if you create 100 threads, only one thread executes Python code at a time.

So threading is best for:

    💤 I/O-bound tasks (waiting on network, files, etc.)

But not good for:

    💪 CPU-bound tasks (math, data crunching, etc.)

⚙️ Step 5 — Multiprocessing Example

When you actually need true parallelism, use multiprocessing —
each process gets its own Python interpreter and memory.

from multiprocessing import Process
import time

def task(name):
    print(f"Starting {name}")
    time.sleep(3)
    print(f"Finished {name}")

p1 = Process(target=task, args=("A",))
p2 = Process(target=task, args=("B",))

p1.start()
p2.start()

p1.join()
p2.join()

print("All done!")

✅ Now, it really runs in parallel on different CPU cores, so also takes about 3 seconds.

GIL	Yes	No
Best for	I/O-bound tasks	CPU-bound tasks
Overhead	Low	High

🧩 Step 1 — The Core Concepts
✅ Iterable

Anything you can loop over with a for loop.
Examples:

[1, 2, 3]       # list
"hello"         # string
(1, 2, 3)       # tuple
range(5)

An iterable has a built-in method __iter__() that returns an iterator.
✅ Iterator

An object that remembers its position while looping.
It gives you one item at a time using next().

Example:

nums = [1, 2, 3]
it = iter(nums)   # calls nums.__iter__()
print(next(it))   # 1
print(next(it))   # 2
print(next(it))   # 3

⚠️ When there’s nothing left, StopIteration is raised.
✅ Sequence

A specific kind of iterable that supports both:

    indexing (x[0])

    length (len(x))

Examples:
list, tuple, str, range — all are sequences.

So:

    Sequence ⊂ Iterable (a subset)

🧠 Step 2 — Generators

A generator is a special kind of iterator —
it produces values on the fly instead of storing them in memory.
Example:

def count_up_to(n):
    count = 1
    while count <= n:
        yield count   # instead of return
        count += 1

gen = count_up_to(3)
print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # 3

✅ The yield keyword pauses the function and remembers where it left off.
Next time you call next(), it continues from there.
⚡ Step 3 — Why Use Generators?

Because they are:

    Memory efficient — they don’t store all data at once.

    Lazy — generate values only when needed.

    Faster for large datasets (like reading huge files, DB streams).

Example:

# Bad: creates a huge list in memory
squares = [x*x for x in range(10_000_000)]

# Good: creates values one by one
squares_gen = (x*x for x in range(10_000_000))

Try:

import sys
print(sys.getsizeof(squares))      # large
print(sys.getsizeof(squares_gen))  # tiny

🧩 Step 4 — Generator vs Iterator vs Iterable
Concept	Returns	Has __iter__()	Has __next__()	Example
Iterable	Iterator	✅	❌	list, tuple, string
Iterator	Value	✅	✅	iter(list)
Generator	Value	✅	✅	function with yield

In Django or data processing:

def fetch_students():
    for student in Student.objects.iterator():  # Django generator

🧩 What is a Context Manager?

A context manager is something that sets up and cleans up a resource automatically.

Typical example:

with open("file.txt", "r") as f:
    data = f.read()
# file is automatically closed here

👉 The with statement handles setup and teardown — no need to manually call f.close() even if an error happens.
🧠 Under the Hood

A context manager is any object that implements two special methods:

__enter__(self)
__exit__(self, exc_type, exc_value, traceback)

Example:

class MyContext:
    def __enter__(self):
        print("Entering context...")
        return "Some value"
    
    def __exit__(self, exc_type, exc_value, traceback):
        print("Exiting context...")
        print("Exception?", exc_type)
        return True  # suppress exceptions if True

with MyContext() as val:
    print("Inside context", val)

Output:

Entering context...
Inside context Some value
Exiting context...
Exception? None

🧹 Why it’s Useful

    Files (automatically close)

    Database connections (commit/rollback)

    Locks in threading (release automatically)

    Network connections

    Temporary resource handling

⚙️ Shortcut: contextlib

You can create a context manager without a class using a decorator:

from contextlib import contextmanager

@contextmanager
def my_manager():
    print("Start")
    yield "Value"
    print("End")

with my_manager() as val:
    print("Inside:", val)

Output:

Start
Inside: Value
End

🧙‍♂️ Magic / Dunder Methods (same thing)

    “Dunder” = Double UNDerscore (like __init__, __str__, __len__).

    “Magic methods” is the nickname for these built-in hooks that let your objects behave like built-in types.

They always look like this:

__something__

💡 Example: Object Lifecycle

class Dog:
    def __init__(self, name):   # Constructor
        self.name = name

    def __str__(self):          # What print() shows
        return f"Dog named {self.name}"

    def __len__(self):          # When len() is used
        return len(self.name)

dog = Dog("Buddy")
print(dog)          # -> Dog named Buddy
print(len(dog))     # -> 5

Here:

    __init__ → runs when object is created

    __str__ → defines readable string

    __len__ → defines how len() works

⚙️ Categories of Magic Methods
Category	Example	Description
Initialization	__init__, __new__, __del__	Creation & cleanup
Representation	__str__, __repr__	How object looks in print() or console
Comparison	__eq__, __lt__, __gt__, etc.	Used in <, ==, etc.
Arithmetic	__add__, __sub__, __mul__	Enable +, -, * on objects
Container	__getitem__, __setitem__, __len__	Act like lists or dicts
Context	__enter__, __exit__	Used in with statements
⚡ Quick Example — Custom Add

class Number:
    def __init__(self, value):
        self.value = value

    def __add__(self, other):
        return Number(self.value + other.value)

    def __str__(self):
        return str(self.value)

a = Number(10)
b = Number(5)
